# DT-001: Project skeleton and health endpoint

| Field | Value |
|---|---|
| Size | S |
| Type | Feature |
| Requirements | FR-01, NFR-04 (health), NFR-05 |
| Depends on | None |
| Test cases | TC-01 |

## Summary
Create the runnable FastAPI application skeleton with `GET /health`, dependency pinning, and the pytest harness so every later story has a place to land.

## Scope
- `app/` package (`main.py`, `__init__.py`), `tests/unit/`, `tests/api/`, `requirements.txt`, `.gitignore`.
- `GET /health` returns HTTP 200 and `{"status": "healthy"}`.
- Endpoint has no side effects and does not touch simulation code.
- App starts locally with `uvicorn app.main:app`.
- Configuration comes from environment variables only (no hard-coded AWS values).

## Out of scope
- `/simulate`, validation, Docker, CI.

## Acceptance criteria
- **Given** the app is running, **when** `GET /health` is called, **then** the response is 200 with body `{"status": "healthy"}`.
- **Given** repeated calls to `GET /health`, **then** the response is identical and no state changes.
- `pytest` runs from the repo root and discovers tests under `tests/`.
- `requirements.txt` has pinned versions.

## Independent test approach
- API test with `TestClient` against `/health` only. No other story is needed.

## Definition of done
- Test for TC-01 passes locally; lint passes; no secrets committed.
