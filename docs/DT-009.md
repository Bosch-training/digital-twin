# DT-009: API documentation and README

| Field | Value |
|---|---|
| Size | S |
| Type | Documentation |
| Requirements | FR-08, Acceptance criterion 13 |
| Depends on | DT-005, DT-006 (to document real behavior); container and deploy sections are filled in by DT-012 and DT-013 |
| Test cases | Documentation review checklist; OpenAPI check |

## Summary
Document endpoints, fields, ranges, examples, and local run/test instructions.

## Scope
- README sections: overview, endpoints, request fields and ranges, success (`COMPLETED`) and rejected (`REJECTED`) examples, error envelope example, local setup, running tests, container build/run, deployment, smoke test.
- Document the decisions made on open questions (Packaging in `FAIL` response, `inspection_result` case sensitivity).
- Interactive docs (`/docs`) reachable, with request/response models and examples populated.

## Acceptance criteria
- A new team member can run the app and the test suite using only the README commands.
- Every example in the README is a valid request/response pair (checked by an automated test that posts the documented examples).
- `/openapi.json` lists `/health` and `/simulate` with the documented fields.

## Independent test approach
- Test that loads the README or example fixtures and executes them against `TestClient`; test that OpenAPI contains both paths.

## Definition of done
- Docs reviewed; example-based test passes.
