# DT-015: Seeded defects and regression evidence (training)

| Field | Value |
|---|---|
| Size | S |
| Type | Training / test evidence |
| Requirements | TR-04, Section 12 (steps 5-6), Section 14 |
| Depends on | DT-002, DT-003, DT-005 with their tests; DT-011 for pipeline evidence |
| Test cases | Defect-detection checks |

## Summary
Prepare one or two known defects on separate branches to show the suite catches them, and capture the defect-to-fix-to-regression-test trail.

## Scope
- Defect A: total time wrongly includes Packaging time on `FAIL`, or Inspection adds time.
- Defect B: Packaging still runs after failed inspection, or `product_id` of 51 characters is accepted.
- For each: branch, failing test output, root-cause note, fix, and a regression test that fails on the defect and passes on the fix.
- Pipeline evidence: red run on the defect branch, green run after the fix.
- A trainer reference solution (known-good) exists on a separate branch.
- Defects exist only on training branches, never on the main branch.

## Acceptance criteria
- Each seeded defect is caught by at least one existing automated test.
- The regression test fails against the defect and passes against the fix (verified by running both).
- Evidence bundle contains test output, CI links, and a short write-up.

## Independent test approach
- Apply the defect patch on a branch and run the suite; no other new functionality is needed.

## Definition of done
- Evidence stored for the final demonstration (TR-04).
