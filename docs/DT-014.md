# DT-014: Post-deployment smoke test

| Field | Value |
|---|---|
| Size | S |
| Type | Test automation |
| Requirements | Acceptance criterion 12, TR-01 (smoke), TR-04 |
| Depends on | DT-001, DT-005 (an endpoint to call); target-agnostic, so it does not require DT-013 |
| Test cases | Smoke: health plus one successful simulation |

## Summary
Create a small, target-agnostic smoke test that takes a base URL and verifies the service is usable.

## Scope
- Script or pytest-marked test (for example `-m smoke`) reading the base URL from an environment variable or argument; no hard-coded hosts.
- Check 1: `GET /health` returns 200 and `status == "healthy"`.
- Check 2: `POST /simulate` with a known valid PASS request returns 200, `COMPLETED`, three stations in order, correct total.
- Timeouts and a limited retry window to allow service warm-up; clear failure messages; non-zero exit code on failure.
- Output is captured as test evidence (console log or JUnit XML).
- Smoke tests are excluded from the default unit/API run.

## Acceptance criteria
- Passes against a local `uvicorn` run and a local Docker container.
- Fails clearly (non-zero exit) against an unreachable URL or a build with a seeded defect.
- Can be invoked from the deployment workflow after DT-013.

## Independent test approach
- Run against localhost; no AWS credentials needed.

## Definition of done
- Smoke output from local and (later) deployed runs is stored as evidence.
