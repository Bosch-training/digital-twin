# DT-002: Simulator core - successful (PASS) flow

| Field | Value |
|---|---|
| Size | M |
| Type | Feature |
| Requirements | FR-03, FR-06 (logic level), NFR-01, NFR-02 |
| Depends on | None (pure Python, no HTTP) |
| Test cases | TC-02 (unit), TC-18 (unit), TC-21 |

## Summary
Implement the fixed three-station simulation (Assembly, Inspection, Packaging) as pure Python in `app/simulator.py` for the `PASS` path, returning a typed result object.

## Scope
- Function such as `simulate(product_id, assembly_time_seconds, inspection_result, packaging_time_seconds)` returning a result model.
- Station order is always Assembly, Inspection, Packaging.
- Result fields: `product_id`, `status`, `stations[]` (`station`, `status`, `duration_seconds`), `total_simulated_time_seconds`.
- `PASS` yields overall `COMPLETED`; Assembly `COMPLETED`, Inspection `PASS` (0 s), Packaging `COMPLETED`.
- `total_simulated_time_seconds = assembly_time_seconds + packaging_time_seconds`.
- No sleeping, randomness, wall-clock, or I/O.
- Inputs are assumed already valid (validation is DT-004).

## Out of scope
- `FAIL` handling (DT-003), validation, HTTP.

## Acceptance criteria
- **Given** assembly 30, `PASS`, packaging 10, **then** status is `COMPLETED`, stations are in order with durations 30/0/10, total is 40.
- **Given** the same input called twice, **then** results are equal.
- Simulating a 300 s assembly returns immediately (no real waiting).

## Independent test approach
- Plain pytest unit tests importing `simulator` directly; no server, no FastAPI imports in the module.
- Use parametrized inputs for time combinations; assert exact station list, not only the total.

## Definition of done
- Unit tests pass; the simulator module has no import from the API layer; type hints present.
