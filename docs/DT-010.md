# DT-010: Test plan, test-condition matrix, and traceability

| Field | Value |
|---|---|
| Size | M |
| Type | Test design |
| Requirements | TR-01, TR-02, TR-03, TR-04 |
| Depends on | None (can start from the requirements alone) |
| Test cases | Covers TC-01 to TC-22 |

## Summary
Produce the test plan and a requirement-to-test traceability matrix before and alongside automation, so coverage gaps are visible.

## Scope
- Test-condition matrix per requirement (FR-01 to FR-08, NFR-01 to NFR-06) with technique used: equivalence partitioning, boundary-value analysis, decision table (`PASS`/`FAIL`), positive/negative, regression, smoke.
- Mapping of TC-01 to TC-22 to a story and a test level (unit, API, smoke).
- Risk-based priority (High/Medium/Low) per test case.
- List of ambiguities and assumptions found in the requirements, with the proposed resolution.
- Added test cases beyond TC-22 where gaps exist (for example case-sensitivity, `product_id` of exactly 50, surrounding whitespace in `product_id`, extra unknown fields, empty body).

## Acceptance criteria
- Each requirement has at least one test case; each test case traces to a requirement.
- Each boundary has a test on, just below, and just above the limit.
- Each automated test name or marker references its TC ID.

## Independent test approach
- Document review against the requirements; verification script or checklist that every TC ID has an automated test (grep for TC IDs in `tests/`).

## Definition of done
- Matrix reviewed and stored in `docs/`; ambiguities resolved or explicitly deferred.
