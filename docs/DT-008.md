# DT-008: Logging and observability

| Field | Value |

| Size | S |
| Type | Feature |

## Summary
Add structured logging for request failures and unexpected errors, without logging secrets or leaking details to clients.

## Scope
- Use the standard `logging` module; log level configurable via environment variable.
- Log a warning for each rejected (400) request with the error code and failing field; do not log the full body.
- Log unexpected exceptions at error level with a stack trace in logs only.
- Log a startup line; do not log every `/health` call at warning level or above.
- Returned status codes are accurate (400 client, 500 server).

## Acceptance criteria
- **Given** an invalid request, **then** a warning record exists and the response has no stack trace.
- **Given** a forced internal exception, **then** an error record with the traceback exists and the client receives a generic 500 envelope.
- No log record contains environment secrets or the raw request body.

## Independent test approach
- pytest `caplog` fixture; force a 500 by monkeypatching the simulator to raise.

## Definition of done
- Log assertions pass; log format is documented in the README.
