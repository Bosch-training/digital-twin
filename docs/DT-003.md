# DT-003: Simulator - failed inspection (FAIL) flow

| Field | Value |
|---|---|
| Size | S |
| Type | Feature |
| Requirements | FR-04 |
| Depends on | DT-002 (result model and simulate function) |
| Test cases | TC-03 (unit), TC-20 |

## Summary
Extend the simulator so `inspection_result = FAIL` stops the line, skips Packaging, and returns `REJECTED` with a reason.

## Scope
- Assembly runs and is `COMPLETED`; Inspection is `FAIL` (0 s).
- Packaging is not executed and contributes no time.
- Overall status `REJECTED`; result includes a reason stating inspection failed.
- `total_simulated_time_seconds = assembly_time_seconds`.

## Open question (confirm before implementation)
FR-04 says Packaging is skipped but FR-03 says station order must not vary. Proposed default: keep Packaging in `stations` with status `SKIPPED` and `duration_seconds` 0, and add a top-level `reason` field (for example `"Inspection failed"`). Record the decision in the README (DT-009).

## Acceptance criteria
- **Given** assembly 45, `FAIL`, packaging 20, **then** status is `REJECTED`, Packaging was not executed, total is 45.
- **Given** `FAIL`, **then** the reason mentions inspection failure.
- Packaging time is ignored for `FAIL` regardless of its value.
- Decision table is covered: `PASS` -> `COMPLETED` / `FAIL` -> `REJECTED`.

## Independent test approach
- Unit tests on the simulator only. Verify via a decision-table parametrized test and a check that changing `packaging_time_seconds` does not change the `FAIL` result.

## Definition of done
- Unit tests pass; the PASS-flow tests from DT-002 still pass (regression).
